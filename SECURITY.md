# Security reporting

Use [GitHub private vulnerability reporting](https://github.com/VINASIG/vinasig-org-directory/security/advisories/new) for exposed credentials, private account data, unsafe tooling or other sensitive findings.

Provide the affected commit, relative path, reproduction steps and impact. Omit plaintext credentials, recovery codes, personal data and unrelated account captures. Do not post sensitive evidence in a public issue.

The directory schema allows public references and contact channels only. Local validation rejects undeclared fields and recognized secret-like patterns. These guards do not certify every possible secret format or establish account ownership. No check signs in, sends email, joins a community or changes an external account.

Report non-sensitive inventory corrections through [repository issues](https://github.com/VINASIG/vinasig-org-directory/issues). A correction needs a maintainer-supplied public reference; do not guess missing channels.
